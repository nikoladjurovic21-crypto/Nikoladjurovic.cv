Free SRS Template for Business Analysts

The structure I use for system and software requirements specifications, as a five-page Word file. Replace the bracketed fields, follow the grey guidance, then delete it.

Download Word .docx, 20 KB PDF preview 136 KB

What Is in It

  • Requirements: problem statement, scope, user scenarios, functional requirements with MoSCoW priority, non-functional requirements with a measure, assumptions.
  • Functional specification: field mapping, numbered business rules with examples, states and transitions, settings, exception handling, process flows, UI controls, API and data model changes.
  • Testing: Given / When / Then acceptance criteria, automated and manual test plans, the UAT release gate.
  • Close-out: simplifications, limitations, open questions with owners, a traceability matrix and a glossary.

How to Use It

  1. Write the problem statement and scenarios first, with real values. They decide everything after them.
  2. Give every requirement, rule and acceptance criterion an ID, and keep the IDs when you send the document to the team.
  3. Fill the traceability matrix last, to check that each requirement has a scenario, an acceptance criterion and a test.
